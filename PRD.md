# PRD — Lipi Lens

**Hackathon:** Modalapada 2.0 (CSE, Ramaiah Institute of Technology). Image track, Challenge 4.
**Deadline:** Submissions due 19 Nov 2026. Registration closes 18 Nov.
**Status:** Draft v0.1, 16 Nov 2026

---

## 1. Problem
Kannada text is everywhere in Karnataka: bus boards, shop signs, milestones, posters, government notices. Visitors, migrants and second-generation speakers who can't read Kannada script get stuck. General-purpose OCR tools often do badly on real-world Kannada signs (stylised fonts, glare, angled shots, mixed Kannada and English). There's also very little openly licensed, labelled data of Kannada scene text to measure or improve them.

## 2. Goal
1. **Prototype:** a camera/upload web app that detects Kannada text in a photo, transcribes it, and shows an English transliteration and translation.
2. **Dataset:** a labelled, privacy-safe, openly licensed set of Kannada scene-text images, contributed to the open Kannada dataset.
3. **Evidence:** measured accuracy on that dataset, so the judges see real numbers.

## 3. Target users
| User | Need |
|---|---|
| Non-Kannada-speaking resident or tourist | "What does this bus board / sign say? How do I pronounce it?" |
| Heritage learner (can speak, can't read) | Hear the text read aloud and see it romanised, to learn the script |
| Researchers / dataset users | Clean, labelled Kannada scene-text data with a benchmark |

## 4. User stories
- **US1:** As a user, I can take a photo or upload one and get the Kannada text it contains within a few seconds.
- **US2:** I see each detected text line in three forms: Kannada script, English transliteration (romanised) and English translation.
- **US3:** I can tap a line to hear it read aloud in Kannada.
- **US4:** I can see where each piece of text is in the image (highlighted box or region).
- **US5:** For bus boards, I get a structured reading: route number, destination, via-stops.
- **US6 (contributor):** I can submit my photo, with a corrected transcription, to the dataset after giving consent. Faces and plates are blurred before saving.

## 5. Scope

### Must have (by 19 Nov)
- Web app that works on mobile: camera capture plus file upload
- Kannada OCR → transliteration → translation pipeline
- Per-line results card with copy button
- Dataset of **≥150** labelled images in the required formats
- Evaluation script that reports character error rate (CER) and word error rate (WER) on the dataset
- Dataset card, README, demo video

### Should have
- Read-aloud (TTS) for each line
- Text-region highlighting on the image
- Bus-board mode (structured fields)
- Contributor flow: consent checkbox, edit transcription, auto blur, save

### Out of scope
- Handwriting recognition
- Native mobile apps (we ship a mobile-friendly web app instead)
- Training a custom OCR model from scratch
- Offline mode

## 6. Functional requirements
| ID | Requirement |
|---|---|
| F1 | Accept JPEG/PNG up to 10 MB. Resize on the server so the long edge is at most 2000 px before inference. |
| F2 | Return JSON: `lines[]` with `kannada`, `transliteration`, `translation`, `bbox` (optional), `confidence`. |
| F3 | Transliteration must be **deterministic**: generated by a rule-based library from the Kannada Unicode, not by the LLM. |
| F4 | All Kannada text is stored and returned as UTF-8 Unicode (no legacy font encodings such as Nudi/Baraha ASCII). |
| F5 | If no Kannada text is found, return an empty result with a friendly message. Never invent text. |
| F6 | Faces and number plates are blurred before any image is saved to the dataset. |
| F7 | Contributions are only saved after the user explicitly ticks a consent box. |

## 7. Dataset specification
Follows the hackathon's data requirements.

- **Images:** JPEG, long edge ≥1280 px, faces and number plates blurred, no personal details visible (phone numbers on private notices etc. are blurred)
- **Labels:** one JSONL record per image:

```json
{
  "id": "lipi_0001",
  "image": "images/lipi_0001.jpg",
  "category": "bus_board | shop_sign | milestone | poster | govt_notice | other",
  "location": "Mathikere, Bengaluru",
  "lines": [
    {
      "kannada": "ಮಲ್ಲೇಶ್ವರಂ",
      "transliteration": "mallēśvaraṁ",
      "translation": "Malleshwaram",
      "bbox": [x1, y1, x2, y2]
    }
  ],
  "script_mix": "kn | kn+en",
  "conditions": ["night", "glare", "angled", "stylised_font"],
  "contributor": "team_member_id",
  "consent": true,
  "license": "CC-BY-4.0"
}
```

- **Splits:** 80% `dev` (used for tuning prompts), 20% `test` (frozen and used only for the final numbers)
- **Diversity goals:** at least 5 categories, plus a mix of day/night, angled and stylised-font shots
- **Labelling rule:** the transcription matches exactly what is written on the sign, including spelling mistakes on the sign. Labels are cross-checked by a second team member.

## 8. Success metrics
| Metric | Target |
|---|---|
| Character error rate (CER) on test split | ≤ 15% |
| Translation judged acceptable (manual check, 50 samples) | ≥ 80% |
| End-to-end latency (p50) | ≤ 6 s |
| Labelled images contributed | ≥ 150 |
| Demo works live on a phone | Yes |

## 10. Risks & mitigations
| Risk | Mitigation |
|---|---|
| LLM hallucinates text on blurry images | Prompt it to output only visible text plus a confidence score. Show low-confidence lines greyed out. Measure on the test set. |
| Inconsistent romanisation | Use a deterministic transliteration library, not the LLM (F3). |
| API rate limits or cost during the demo | Cache results by image hash. Keep pre-run demo images as a fallback. |
| Privacy slip in the dataset | Auto blur plus a manual review pass before export. Run a checklist on every image. |
| Not enough time to label | Pre-fill labels with model output. Humans only correct them, which is faster than typing from scratch. |
